## 1. 实施边界

本计划明确四阶段：第一阶段实现并实际执行、复验和分析；第二阶段用户人工抽验；第三阶段旧 AI 内容与 CI 关系另行讨论；第四阶段才编写测试 skill。目录调整不意味着重写。已有实现若仅需变更文件路径、参数或入口，保留其内部逻辑和已有测试；新增逻辑只覆盖当前明确缺口。

用户已授权开始第一阶段：先提交已确认的设计与计划文档，再开发和验证；开发后的修改保留在工作区供用户审阅，不提交。执行计划时，涉及协议和长期维护的设计选择在 P1 给出具体样例供确认，其余任务按已确认契约落地。

## 3. 用例范围

### 3.1 单设备：沿用现有 20 步正向、10 步逆向内容

输入：`im_flutter_sdk/example/scripts/script_500_apis_positive.json`、`script_500_apis_negative.json`。迁移后按功能分组，新增断言；保留每个原步骤 ID 的去向及不执行原因。

| 功能 | 保留内容 | 需要增强的检查 |
|---|---|---|
| 未读数 | 查询、清指定会话、清全部；空会话错误 110 | 清理后确为零；若前值为零不宣称验证了非零到零转换，交互场景用实际收消息补充 |
| 消息编辑 | 自发消息修改正文与 attributes；缺失消息 500 | 修改后的数据可读回并一致；服务未开通记录环境阻塞 |
| 群配置 | 建群、修改、销毁；非法成员及缺失群 600 | 修改值与读取结果符合契约，资源归属与失败清理明确 |
| 已读回执 | 四个回执 API；混合批次成功、全不可解析批次 110 | 单设备保持回归基线，非空回执内容由多设备用例补齐 |
| 设备与 Token | 在线设备、renewToken、kickDevice/kickAllDevices；无效 Token 303、空 Token 104 | 使用本次设备的真实 resource，核实归属，不把列表第 0 项当成本端；踢设备步骤放最后并隔离运行 |

原 `sendMessage`／`destroyGroup` 等准备与清理步骤允许共享，不按步骤数量机械生成文件。已知缺失消息分页崩溃继续屏蔽并显式记录，不能为获得全绿改变 SDK 错误语义。

### 3.2 多设备：三个典型正向场景

依据：[02-contract](../../porting/5.0.0/02-contract.md) 的同步及回执契约、[04-verification](../../porting/5.0.0/04-verification.md) 的真实执行和历史缺口、[acceptance-report](../../porting/5.0.0/acceptance-report.md) 中尚未覆盖的双账号事件。历史文档包含被后续更正的记录，以后续结论结合当前源码核实，不能照搬过时错误码或环境选择逻辑。

| 场景 | 主脚本编排 | 断言和前置条件 |
|---|---|---|
| M1 `data-sync` | A 登录并准备可同步数据 → B 监听就绪 → 放行 B 同账号登录 → B 汇报同步事件与数据 | 同账号多设备策略可用；核实数据类型、同步配置及触发条件；同步 start/finish 类型匹配、无错误、数据确实存在；数据库事件按契约验证 |
| M2 `direct-read-receipt` | 两账号登录、双方监听就绪 → A 发消息并输出 ID → B 接收该消息并发回执 → A 检查回调 | 消息／会话 ID 一致，单聊回执字段符合契约；使用 B 实际接收并已落库的消息；不靠伪造接收消息对象通过 |
| M3 `group-read-receipt` | REST 准备两账号所在临时群 → A 发需回执消息 → B 接收并发回执 → A 检查事件、本地汇总和分页详情 → 清理 | 群回执服务可用；详情含本次消息及 B 的成员信息；汇总数量按受控成员状态检查；Android totalCount 可空，不要求与 iOS 完全同形 |

每个场景三个文件：`5.0.0-multi-<feature>-positive-main.json`、`...-device1.json`、`...-device2.json`，放在 `testing/scripts/5.0.0/multi/<feature>/`。设备数量不进入 `multi` 名称，角色在主脚本中声明。

执行顺序为 M2 单聊回执 → M3 群聊回执 → M1 数据同步；编号保留为场景标识，不表示执行顺序。默认可先用 Android 与 iOS 各一台组成双设备组合；记录实际角色分配，在可用设备上交换发送／接收角色验证两端回调。未测设备组合明确列出。三场景全部是待实现用例，不引用历史报告冒充本次结果。
