# HIM-23835 iOS 多设备 Thread 回调复验

## 问题

iOS 原生插件将 Thread 多设备事件的 ID 写入 MethodChannel payload 的
`threadId` 字段，而 Dart 公共层读取 `target`，导致
`ChatMultiDeviceEventHandler.onChatThreadEvent` 收到的 Thread ID 为空。

修复后 Android、iOS 和 Dart 统一使用 `target`。

## 复验入口

```bash
bash im_flutter_sdk/example/bugs/HIM-23835/HIM-23835.sh
```

指定独立环境配置和模拟器：

```bash
bash im_flutter_sdk/example/bugs/HIM-23835/HIM-23835.sh \
  --config /absolute/path/thread-enabled-config.json \
  --devices <mirror-udid>,<controller-udid>
```

工单执行器位于 `im_flutter_sdk/example/bugs/HIM-23835/run.dart`。它使用两个
iOS 模拟器登录账号 A：镜像端保持在线并接收回调，控制端依次执行 Thread
UPDATE 和 KICK。账号 B 仅作为 Thread 成员，不需要第三台设备。

## 配置

配置按以下顺序解析：

1. `--config <path>`；
2. `HIM_23835_CONFIG` 指向的 JSON 文件；
3. 一组完整的环境变量：`E2E_REST_API`、`E2E_APP_KEY`、
   `E2E_CLIENT_ID`、`E2E_CLIENT_SECRET`、`E2E_USER_A_ID`、
   `E2E_USER_B_ID`；
4. 现有 `im_flutter_sdk/example/config.local.json`，仅作为只读回退。

脚本自动获取 App Token 和两个用户 Token，并在系统临时目录生成权限为
`0600` 的 `API_CONFIG`。运行过程不修改 `config.local.json` 或
`lib/env.dart`，退出时删除临时配置。

测试环境必须已开通 Thread 功能，否则 REST 创建 Thread 会返回
`403 thread not open`，脚本会清理已经创建的群组后退出。

## 执行流程

1. 通过 REST 创建群组，将账号 A 设为群主并加入账号 B。
2. 通过 REST 发送群消息，使用返回的消息 ID 创建 Thread。
3. 通过 REST 将账号 B 加入 Thread。
4. 启动镜像端 A，确认登录和连接成功。
5. 控制端 A 通过 Flutter SDK 更新 Thread 名称。
6. 确认镜像端收到 `CHAT_THREAD_UPDATE`，且 Thread ID 与创建结果一致。
7. 控制端 A 通过 Flutter SDK 踢出账号 B。
8. 确认镜像端收到 `CHAT_THREAD_KICK`，Thread ID 一致且 `userIds` 包含 B。
9. 通过 REST 删除 Thread 和群组，并恢复模拟器原始启动状态。

## 产物

报告写入 gitignored 的
`reports/5.0.0/HIM-23835-<timestamp>/`。失败路径同样执行资源清理，并在
`run.json` 和 `summary.md` 中记录失败阶段与清理结果。

通用 REST 资源能力位于
`im_flutter_sdk/example/tool/rest_resource_client.dart`，覆盖群组、聊天室和
Thread 的创建与删除、群文本消息发送以及 Thread 成员添加。
