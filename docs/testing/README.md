# 测试指南

按验证目标选择测试类别；账号数量不等于运行中客户端数量。已有场景可跨版本复用，不需要为每次升级复制一套。

| 类别 | 使用场景 | 用例及入口 | 设计说明 |
|---|---|---|---|
| CI 回归 | 基础行为、关键边界、已修复缺陷的持续回归 | `im_flutter_sdk/test/`、`im_flutter_sdk/example/integration_test/`；`tool/ci/` | [CI](2026-11-09-ci.md) |
| 单设备平版 | 一台客户端即可验证的参数、返回值、本地状态和错误行为 | `testing/single/cases/`；`make auto-report` | [单设备](2026-11-09-single-device.md) |
| 多设备平版 | 接收方通知、申请与接受、回执、订阅、同账号多端同步 | `testing/multi/data/`；多设备 CLI | [多设备](2026-11-09-multi-device.md) |

`im_flutter_sdk/example/lib/` 提供共用 API 注册、事件观测、脚本执行和人工界面。人工模式用于自由抽验，不是另一套自动用例。`tool/flow_runner/` 保持独立解释器；CI 保持 Flutter 标准测试入口。

## 共同原则

- 先定义目标、前置条件和核心断言。准备动作不能提前完成被测行为；不为增加覆盖率机械枚举 API 或参数。
- 每项变更评估三类测试的适用性，不要求每项都新增三份用例。纯编解码优先单元／契约测试；仅需一台客户端时使用单设备。
- 正向、逆向按明确契约选择，不猜错误码。创建消息、请求返回、发送最终回调和对方接收是不同观察点。
- 使用本轮资源关联事件，监听在触发前就绪，等待有超时；不靠固定 sleep 或历史事件证明成功。
- 仅检查目标所需状态。多设备好友申请接受后检查双方本地联系人包含对方；CI 删除联系人用例检查调用完成即可。
- 清理本例创建的资源或恢复修改值，不删除账号历史数据。业务失败、准备失败、清理失败分别记录。
- 不为绕过 SDK 缺陷放宽正确断言。记录通过、失败、阻塞、未执行和暂停；单元通过不等于设备场景通过。
- 结果注明实际 Flutter／native 依赖、平台、命令和证据；分支名不证明 native 版本。排序关闭不要求结果必须与排序开启不同。

## 文档与结果

每次运行自动生成且 Git 忽略的正式报告，见[自动测试报告](2026-11-09-reports.md)：CI 报告及版本升级报告分开，版本升级内再分别统计单设备、多设备；支持全部范围或单项执行，报告链接原始证据。

运行命令见 [测试入口](../../testing/README.md) 和 [开发环境](../../CONTRIBUTING.md)。具体语法、配置、协议由各工具文档维护，版本覆盖和验证结论进入 `docs/porting/<版本>/`，原始日志进入各工具忽略的报告目录。历史报告只代表当时的执行结果。

版本覆盖规划和历史分析：[5.1.0 覆盖表](../porting/5.1.0/2026-11-09-test-coverage.md)及[历史验证与问题表](../porting/5.1.0/2026-11-09-test-verification.md)。这些被追踪的文档不代替每次执行自动生成的报告。历史已知失败及 M2 免打扰同步暂缓决定仍保留；实际本次结果以运行目录内的正式报告为准。

当前入口归类及迁移验证见 [2026-11-10 入口归类记录](2026-11-10-ci-entry-reclassification.md)；五个稳定入口已整理，已有会话专项配置归属仍待确认。
