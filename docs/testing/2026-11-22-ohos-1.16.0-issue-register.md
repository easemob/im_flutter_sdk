## 问题清单

### ISSUE-1 多端群组事件未知 event 码击穿 test binding（B 级）

- **现象**：contact 套件运行中 `_onMultiDeviceGroupEvent` 抛 `Null check operator used on a null value`（chat_client.dart:146），platform channel 处理器异常导致该套件后续全部用例 "did not complete"。
- **复现率**：3 轮全量中 2 轮出现（1.15 native 1 次、1.16.0 第 1 次），2 轮插桩全量 0 出现；插桩（打印原始 event 码）两轮均未抓到事件送达，属服务端延迟投递触发，非必现。
- **已确认事实**：
  - native 1.15.0 / 1.16.0 的 `.d.ets` `MultiDevicesEvent` 声明完全一致（2-6 / 10-33 / 60-64），其中 30-33 曾缺失于 Dart converter（本次已修，见 A-1）；
  - 首崩发生在 converter 已补 30-33 之后 ⇒ **崩溃码不在声明枚举内**；
  - ArkTS 侧 `event as number` 是强转不是转换，native `.so` 理论上可透传声明外的码（如服务端驱动的更新事件类型）；
  - `libhyphenate.so` 符号已剥离，无法离线枚举实际码表。
- **影响**：单事件即可团灭一个套件（级联 "did not complete"）。
- **建议**：handler 防御化——converter 返回 null 时记录原始码并降级为 `UnKnow` 分发，不中断事件链（与 4.x `!` 写法有意分歧，需用户确认）；同时把"抓原始码"作为后续 nightly 的观察项。

### ISSUE-2 FL-EVENT-205 群成员加入回调超时（C 级 → 记录只跟踪）

- **现象**：等待"本设备用户加入 peer 所建群"的 `onMemberJoinedFromGroup` 40s 超时；期间收到一个无关的延迟事件（peer 加入另一群，谓词不匹配）。
- **复现率**：今日 3/3（1.15 一轮 + 1.16.0 两轮）。
- **归因**：服务端事件管道延迟/乱序——预期事件迟迟未到，非用例自身问题（谓词、账号归属已核实）。与 4.x 台账中 FL-CONV-017 / FL-PRESENCE-006 同类。
- **处置**：不改代码，登记跟踪；nightly 观察复现率。

### ISSUE-3 FL-CONV-030 按时间删除本地及服务端消息 68ms 超时（C 级 → 记录只跟踪）

- **现象**：`waitForCi` 首轮轮询即抛 `TimeoutException after 0:00:00.068`，后续断言未执行。
- **复现率**：3 轮中 1 轮出现（首轮挂、两轮通过），间歇性。
- **归因**：时序类，与 ISSUE-2 同源（服务端/本地异步状态未就绪）。68ms 表象疑为前序操作耗时计入 watch 后的残留窗口，未完全坐实。
- **处置**：不改代码，登记跟踪。
