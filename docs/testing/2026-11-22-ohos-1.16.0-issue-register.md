## 问题清单

### ISSUE-1 多端群组事件未知 event 码击穿 test binding（A 级，已修复）

- **现象**：contact 套件运行中 `_onMultiDeviceGroupEvent` 抛 `Null check operator used on a null value`（chat_client.dart:146），platform channel 处理器异常导致该套件后续全部用例 "did not complete"。
- **复现率**：3 轮全量中 2 轮出现（1.15 native 1 次、1.16.0 第 1 次），2 轮插桩全量 0 出现；插桩（打印原始 event 码）两轮均未抓到事件送达，属服务端延迟投递触发，非必现。
- **已确认事实**：
  - native 1.15.0 / 1.16.0 的 `.d.ets` `MultiDevicesEvent` 声明完全一致（2-6 / 10-33 / 60-64），其中 30-33 曾缺失于 Dart converter（本次已修，见 A-1）；
  - 首崩发生在 converter 已补 30-33 之后 ⇒ **崩溃码不在声明枚举内**；
  - ArkTS 侧 `event as number` 是强转不是转换，native `.so` 理论上可透传声明外的码（如服务端驱动的更新事件类型）；
  - `libhyphenate.so` 符号已剥离，无法离线枚举实际码表。
- **根因结论**：Dart 侧 `convertIntToChatMultiDevicesEvent(...)!` 对未知码无防御，平台通道处理器抛异常中断整个套件。ArkTS wrapper 与 4.x Android wrapper 均为原生 int 透传（`event as number` / `data.put("event", event)`），wrapper 无缺陷；native 透传声明外事件码属鸿蒙 native SDK 侧问题（服务端推送新事件类型时旧 native 无白名单过滤），Flutter 层无法补语义，需提工单给 native 团队。
- **影响**：单事件即可团灭一个套件（级联 "did not complete"）。
- **修复**：chat_client.dart 三个多端 handler（group/contact/conversation）统一走 `_parseMultiDevicesEvent`——converter 返回 null 时 `ChatLog.e` 记录原始 event 码并丢弃事件，不再崩溃（用户裁决：未知事件不处理、error 级日志，不降级为 UnKnow 分发）。修复后 nightly 日志可直接抓到原始码，用于 native 侧定位。

### ISSUE-2 FL-EVENT-205 群成员加入回调超时（C 级 → 记录只跟踪）

- **现象**：等待"本设备用户加入 peer 所建群"的 `onMemberJoinedFromGroup` 40s 超时；期间收到一个无关的延迟事件（peer 加入另一群，谓词不匹配）。
- **复现率**：今日 3/3（1.15 一轮 + 1.16.0 两轮）。
- **归因**：服务端事件管道延迟/乱序——预期事件迟迟未到，非用例自身问题（谓词、账号归属已核实）。与 4.x 台账中 FL-CONV-017 / FL-PRESENCE-006 同类。
- **处置**：不改代码，登记跟踪；nightly 观察复现率。

### ISSUE-3 FL-CONV-030 按时间删除本地及服务端消息 68ms 超时（C 级 → 记录只跟踪）

- **现象**：`waitForCi` 首轮轮询即抛 `TimeoutException after 0:00:00.068`，后续断言未执行。
- **复现率**：3 轮中 1 轮出现（首轮挂、两轮通过），间歇性。
- **归因**：时序类，与 ISSUE-2 同源（服务端/本地异步状态未就绪）。68ms 表象疑为前序操作耗时计入 watch 后的残留窗口，未完全坐实。
- **处置**：不改代码，登记跟踪。

## 待提工单（周一 2026-11-23 提交，用户决策：周日休息日）

**项目**：HIM（j1.private.easemob.com），问题归属鸿蒙 native SDK（`@easemob/chatsdk`）团队，Flutter 侧已防御化（ohos f102bacd / ohos-1.16.0 a436b1a6，修复后 nightly 日志会直接打出原始码，抓到后补进工单）。

- **标题**：【鸿蒙 native SDK】MultiDevicesListener 透传 MultiDevicesEvent 声明枚举外的事件码，服务端推送新事件类型时无白名单过滤
- **现象**：`@easemob/chatsdk` 1.15.0 / 1.16.0 的 `MultiDevicesListener`（onGroupEvent / onContactEvent / onConversationEvent）会收到不在 `.d.ets` 声明枚举（2-6 / 10-33 / 60-64，两版本逐字节一致）内的事件码；ArkTS 强转 `event as number` 后透传，Flutter 层无法映射语义。
- **复现路径**：REST（app token）建群→加人→移除/销毁群，产生的多端群同步事件被服务端延迟 1-3 分钟投递到正在运行其他套件的客户端；im_flutter_sdk ohos 线 integration 全量 3 轮中 2 轮复现（1.15.0 一轮、1.16.0 一轮），崩溃点在紧邻套件 FL-CONTACT-017 开始前 1 秒内。
- **影响**：接入方按官方枚举做 exhaustive 处理时会因未知码出错；Flutter SDK 修复前直接空检查崩溃、团灭整个测试套件；修复后未知事件被丢弃，多端同步语义静默丢失。
- **证据**：`im_flutter_sdk/.worktree/ohos/artifacts/ohos-logged_in_base.log:183-187`（同轮 FL-EVENT-205 自身 40s 超时，服务端延迟实证）；崩溃日志 `ohos/artifacts/ohos-logged_in_contact.log:54-61`；本台账 ISSUE-1。
- **期望**：① 提供 native 实际可派发的完整事件码表（libhyphenate.so 符号剥离，Flutter 侧无法离线枚举）；② 服务端新增事件类型时同步更新 `.d.ets` 声明；③ 或 native 层对未知码做白名单过滤/显式 Unknown 语义。
