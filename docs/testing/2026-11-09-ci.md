# CI 回归测试

CI 保护公开契约明确、数据可控、有长期回归价值的行为。纯 Dart 模型、参数传递与序列化放在 `im_flutter_sdk/test/`；依赖 native、数据库和服务端的行为放在 `im_flutter_sdk/example/integration_test/`。

## 设计规则

- 设备测试保持单设备执行。可准备对端账号、群组或关系，不依赖另一个在线客户端。
- 每例独立准备、执行、断言和收尾，不能依赖其他用例的执行顺序或遗留资源。
- 固定五个入口：`logged_out_test.dart`、`logged_in_base_test.dart`、`logged_in_group_test.dart`、`logged_in_contact_test.dart`、`logged_in_user_info_test.dart`。分类首先看登录前置，再看会话、群组和联系人三个同步开关；用户资料单列专项配置。所有入口开启会话同步，仅群组入口开启群组同步、联系人入口开启联系人同步、用户资料入口开启 `enableUserInfo`。
- 登录分类表示前置状态，不限制用例内退出或重新登录。基础入口承载认证、消息、会话和本地数据库；群组、联系人、用户资料 API 分别归对应入口。群消息收发不要求群组列表同步，消息用例准备好友关系也不改变其基础类归属。
- 普通用例只补 `modules/` 对应业务模块的现有注册函数，辅助能力放 `support/`；保留编号并同步 `native-case-mapping.json`。不得因补用例修改五个稳定入口、新增或重命名入口、改变共享配置或修改 workflow/运行脚本。若新增业务模块确需调整入口 import 或注册接线，也要先说明并取得确认，不默认豁免。
- 初始化依赖项全部显式指定，不依赖默认值；“基础配置”不表示 SDK 省略参数的默认行为。不同初始化必须冷启动应用。`nightly_local.sh` 保持总入口，循环调用既有设备 runner，不新增调度层。完整配置和编号归属见 [CI 说明](../../im_flutter_sdk/docs/ci/flutter-only-ci.md)。
- 三个同步开关与 `autoLoadConversations`、`enableChatroomConversation` 相互独立。现有 FL-CONV-011/012 及 FL-CONV-013 开启聊天室会话的特殊配置迁移待确认；不能修改其正确断言来适配常规入口。今后遇到固定配置无法承载的场景，先记录冲突并确认处理方式，不能自行扩展入口或批次。
- 联系人删除仅断言 API 完成；REST 用于准备和恢复。发送测试关联最终回调，不能以构造消息或接口返回代替发送结果。
- 使用确定的契约预期，不将任意异常视作负向通过；SDK 或环境问题保留失败证据。

## 执行

从仓库根运行：

```bash
FORMAT_BASE_SHA=HEAD bash tool/ci/run_quality.sh
bash tool/ci/smoke_local.sh android
bash tool/ci/smoke_local.sh ios
bash tool/ci/nightly_local.sh android
bash tool/ci/nightly_local.sh ios
```

Smoke 无需账号；Nightly 需要 `E2E_APP_KEY`、`E2E_USER_ID`、`E2E_REST_API`、`E2E_CLIENT_ID`、`E2E_CLIENT_SECRET`，工具自动准备 Token 和 peer。Android 入口使用已启动的 `emulator-5554`。设备日志在 `artifacts/`。

正式统计报告自动写入 Git 忽略的 `artifacts/ci/<run-id>/summary.md`，终端打印路径；单个用例可通过 `CI_TEST_NAME=<名称正则>` 调用既有设备 runner。输出文件、分类口径及重建命令见[自动测试报告](2026-11-09-reports.md)。

质量检查之外还需运行 example 和测试工具的全部单测，命令见 [测试入口](../../testing/README.md)。CI 工作流与具体配置见 [CI 说明](../../im_flutter_sdk/docs/ci/flutter-only-ci.md)。
