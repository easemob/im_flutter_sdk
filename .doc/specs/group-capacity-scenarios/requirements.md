# Group 容量场景参数化

## User Story

作为 Group 自动化测试维护者，我希望同一套群组 case 能以默认容量 200 和扩容容量 3000 分别运行，从而验证大容量群创建场景，同时不复制和长期维护两份相同的 case 代码。

## Acceptance Criteria（EARS）

1. 当未提供容量场景参数运行 Group case 时，系统应继续以 `maxCount=200` 创建常规群，保持现有默认回归行为和断言不变。
2. 当以显式容量场景参数 `--group-create-max-count=3000` 运行 Group case 时，所有常规建群请求及其 `maxUserCount` 断言应使用 `3000`，且测试函数、业务步骤和 case 名称不得复制。
3. 当 case 的测试目的本身是容量边界时，系统应保留该 case 明确指定的 `maxCount` 值；包括 `0`、`-1`、`1` 和 `2`，不得被场景参数覆盖。
4. 当传入小于等于零的容量场景参数时，pytest 应在执行任何测试前报出清晰的参数错误，避免产生无效测试环境写入。
5. 当容量场景实现完成时，Group 台账应记录默认 200 与扩容 3000 的执行命令、边界值豁免规则和针对性验证结果。
