## 十一、送达回执结论反转 + isPeerRead 断言（2026-08-17 实跑）

### 1. 送达回执可用（之前"不可用"结论错误）
- **5.0 契约**：消息设 `needReadReceipt=true` → 服务端自动发 DELIVER_ACK（onMessagesDelivered + onMessageDeliveryAck + hasDeliverAck=True）；不设 → 恒不收（"收不到"的真实原因）
- 11 个 case 已转正（去 skip + needReadReceipt=true）：delivery_ack、typed_delivery_ack×6、combine_delivery_ack、location_delivery_ack、missing_message_delivery_ack×2 —— 全 PASS
- 已读回执区分：need=true 只是资格；送达自动到手，已读需 B 主动调 asyncSendMessageReadReceipts（ackMessageRead）

### 2. hasDeliverAck 确定性（不是随机/ignore）
- 设 needReadReceipt=true + 送达后 = **True**；未设 = **恒 False**（发送方/撤回副本/接收方向均 False，已实证）
- 断言：设 flag 的已读/送达事件锁 True；未设的锁 False（已统一修改 operations/extended_operations 共若干处）

### 3. isPeerRead / readReceiptCount（wrapper 补字段 + 断言）
- **EMHelper.java 已补**：`isPeerRead()`（isAcked 5.0 名）+ `readReceiptCount()`（groupAckCount 5.0 名）-> json 输出（已编译装 4 台）
- **isPeerRead 变化点**：B 调 ackMessageRead 后（onMessagesRead 事件）→ True；之前（发送/接收/送达）→ False
- 断言已补：送达/接收锁 False（_assert_delivered_message + location + operations 各处）；已读事件锁 True（ack_read_strict + _assert_read_event + crud ×2）
- **Dart model 未补**（isPeerRead/readReceiptCount 字段）→ 待做（P2 后续）
