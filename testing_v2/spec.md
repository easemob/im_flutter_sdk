# 规则与边界

1. 本文只定义系统规则、职责边界和协作约束。
2. 代码和文档只描述当前系统，不记录设计参考来源、版本间迁移思路、修改过程或改进对比。
3. 内容须有依据，事实陈述清晰、准确、无歧义；非必要不添加，不写重复说明或过程话术。
4. 围绕用户当前目标执行，只做明确要求及完成任务必需的工作，不顺手处理其他事项。
5. 扩展建议须与当前问题直接相关；建议不等于授权，经用户确认后才纳入执行。
6. 沟通先说结论和关键依据，按问题所需提供细节，不重复已知背景或添加无关内容。
7. 执行中遇到尚未确认的重大变更，包括架构、职责边界、数据结构、接口、目录组织、依赖或既有行为的调整，须先说明原因、改动范围和影响，取得用户确认后再实施；不得以完成任务为由擅自新增或修改范围外的文件、代码。已确认范围内的必要实现无需重复确认。
8. 模块开发以交付契约为边界：上游按约定格式交付，下游使用前验收，不合格立即停止依赖操作并记录差异。缺陷按交付、验收或编排的实际问题修复；不得为使流程通过而转移职责、放宽校验或增加隐式兜底。契约本身需要调整时，遵循第 7 条。
