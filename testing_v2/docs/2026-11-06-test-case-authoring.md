# 编写用例

目标：将经用户确认的测试场景编写为可执行用例。

编写用例属于执行前的准备工作，不是每轮执行步骤；用例完成并验证通过后可重复执行。

## 规则

1. 与用户讨论并确认测试场景、前置条件和通过标准，据此确定所需数据及设备数量。
2. 用例须包含正向和逆向测试：正向验证正常行为，逆向验证异常输入或条件下的预期行为。
3. 用例按设备数量分为单设备和多设备，两类均需覆盖适用的正向、逆向场景。单设备覆盖绝大部分场景；多设备覆盖单设备无法完成的交互场景，能用单设备完成的，不增加多设备协同。
4. 用例语法遵循 [flow_runner 使用说明](../../tool/flow_runner/README.md)：YAML 表达流程，JSON 保存命令及数据；命令和参数依据 SDK 公开接口。
5. 编写时核对 example 执行端是否支持对应命令；缺少支持时单独提出，经用户确认后补充，不能将无法执行的用例作为可用产物。
6. 正式执行中失败的用例必须复验，查明属于用例问题，还是 SDK 缺陷、设备故障、环境问题、数据准备问题等其他原因。此项复验要求不适用于用例开发和调试阶段。
7. 不得为绕过 SDK 问题修改正确用例或降低断言要求。

## 文件命名

- 用例 YAML、命令 JSON 放在 `data/`，命名为 `<版本>-<single|multi>-<场景>-<positive|negative>.<yaml|json>`。
- 同一用例对应的 YAML、JSON 使用相同主文件名，例如 `5.0.0-multi-presence-positive.yaml` 和 `5.0.0-multi-presence-positive.json`。
- 场景名使用小写英文，多个单词以 `-` 连接。静态用例可重复使用，文件名不带运行时间或设备实例标识。
