# 多设备协同测试执行流程

目标：完成多设备协同系统测试。

[编写用例](2026-11-06-test-case-authoring.md)属于执行前的准备工作。用例完成并验证通过后可重复执行，无需每轮重新编写。

## 执行流程

1. [数据准备](2026-11-06-data-preparation.md)
2. [设备准备](2026-11-06-device-preparation.md)
3. [执行用例](2026-11-06-test-execution-troubleshooting.md)
4. [汇报总结](2026-11-06-reporting.md)
5. [必要清理](2026-11-06-cleanup.md)

## 执行入口与编排

1. 由 Dart `main` 提供分环节操作和全流程自动化；分环节操作用于排查和调试，全流程用于取得测试结果，两种方式复用同一套模块实现。
2. Dart 编排层负责执行顺序、本轮数据传递、失败时继续或暂停，以及报告和收尾；具体操作由各模块负责。
3. 全流程共用 `runId`；分环节操作须明确使用哪一轮的输入和产物，便于复现问题。
4. 宿主命令由 Dart 调用；`tool/flow_runner` 负责用例内部控制流，Dart 编排层负责整个测试任务的生命周期。

## 日志规则

目的：快速定位问题。以下规则适用于全部执行阶段。

1. 日志应能定位时间、测试轮次、阶段和步骤；涉及设备时标明设备。
2. 记录阶段执行及模块调用的开始、结束、必要输入和关键结果，能够判断流程停在哪里。
3. 调用宿主命令时保留标准输出、错误输出及退出状态；失败时保留原始错误和调用上下文，不能只有“执行失败”。
4. 工具日志与被测应用日志应能按测试轮次和设备关联；报告提供对应日志和证据的位置。
5. 日志中的敏感数据须脱敏，不输出 Token、密码、密钥等敏感值。
