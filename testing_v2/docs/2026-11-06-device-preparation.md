# 设备准备

目标：管理和操作设备。

范围：Android、iOS 模拟器；真机和沙箱暂不纳入。

通过 Dart `dart:io` 的 `Process.run`、`Process.start` 调用宿主命令，如 `adb`、`emulator`、`xcrun simctl`，获取输出、退出码和进程状态。

## 基础操作

| 操作 | 含义 |
|---|---|
| 查找设备 | 查找宿主环境中的模拟器。 |
| 查看设备 | 查看可用模拟器及运行状态。 |
| 启动设备 | 启动指定模拟器。 |
| 关闭设备 | 关闭指定模拟器，保留实例及数据。 |
| 销毁设备 | 删除指定模拟器实例及其数据。 |
| 安装应用 | 将已有的示例应用构建产物安装到指定模拟器。 |
| 卸载应用 | 从指定模拟器卸载示例应用。 |

## 职责边界

- 基础操作可独立调用，由测试流程组合使用。
- 安装操作接收已有构建产物，不负责编译；由测试流程在产物就绪后调用。

## 产物与启动

- 设备模块返回实际运行设备 ID 和就绪检查结果，由编排层保存为 `devices.json`；账号分配由编排层按调用输入确定。
- 启动模块获取本次 App 的连接及握手信息，由编排层保存到私有 `run.json`；执行模块重新核验后使用，不隐式安装或重启 App。
- Android 从指定设备的 logcat、iOS 从模拟器系统日志采集启动凭据，采集先于启动，日志写入前脱敏。启动日志和握手返回的 `instanceId` 不作跨来源比较。
- 每次用例执行及复验使用新 App 实例；重复启动使该设备的旧连接失效，保留历史记录。`run` 通过 `--launch` 指定一组完整启动结果，不拼接或自动选择。连接字段、采集与生命周期规则见[执行规格 §3](../../docs/spec/2026-11-06-testing-v2-spec.md#3-设备准备编译与安装运行)。

## 文件命名与存放

- 设备运行信息及日志放在 `tmp/<runId>/`，设备相关文件使用流程角色名区分，例如 `deviceA.log`、`deviceB.log`；记录中保留对应的实际设备标识。
- `runId` 遵循[执行用例的轮次规则](2026-11-06-test-execution-troubleshooting.md)，同一轮设备产物共用该标识。
