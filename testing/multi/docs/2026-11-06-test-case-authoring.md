# 编写用例

目标：将经用户确认的测试场景编写为可执行用例。

编写用例属于执行前的准备工作，不是每轮执行步骤；用例完成并验证通过后可重复执行。

## 规则

1. 与用户讨论并确认测试场景、前置条件、允许的准备动作及通过标准，据此确定所需数据及设备数量；准备动作不能提前完成被测业务行为。
2. 按目标和明确契约选择正向、逆向场景，不要求每个正向用例都配套逆向；共同原则见 [测试指南](../../../docs/testing/README.md)。
3. 用例按设备数量分为单设备和多设备，分别覆盖适用的正向、逆向场景。本工具负责多设备协同，单设备使用 `testing/single/`；多设备覆盖单设备无法完成的交互场景，能用单设备完成的，不增加多设备协同。
4. 用例语法遵循 [flow_runner 使用说明](../../../tool/flow_runner/README.md)：YAML 表达流程，JSON 保存命令及数据；命令和参数依据 SDK 公开接口。
5. 编写时核对 example 执行端是否支持对应命令；缺少支持时单独提出，经用户确认后补充，不能将无法执行的用例作为可用产物。
6. 正式执行中失败的用例必须复验，由 AI／人工检查证据后显式发起，查明用例、SDK、设备、环境或数据等问题；尚未复验标为“待复验”，不免除复验要求。开发、调试阶段不强制复验。
7. 不得为绕过 SDK 问题修改正确用例或降低断言要求。
8. 当前用例通过 `$global` 引用账号、设备及业务数据；账号使用 `$global.account.account1` 等统一编号，设备通过 YAML `agent` 选择；JSON 的 `data` 声明输入，`steps` 保存命令，`requiredBindings` 声明必要验证。字段及读写规则遵循[执行规格 §2](../../../docs/spec/2026-11-06-testing-v2-spec.md#2-数据准备)和[§4](../../../docs/spec/2026-11-06-testing-v2-spec.md#4-用例与执行)，不在命令对象中混入控制流。
9. 建轮时固定用例副本，准备、执行及汇报使用同一份定义。修改用例后以新轮次验证，不能在已有轮次内静默替换命令或预期。

## 文件命名

- 用例 YAML、命令 JSON 放在 `data/`，命名为 `<版本>-<single|multi>-<场景>-<positive|negative>.<yaml|json>`；当前使用 `multi`。
- 同一用例对应的 YAML、JSON 使用相同主文件名，例如 `5.0.0-multi-presence-positive.yaml` 和 `5.0.0-multi-presence-positive.json`。
- 场景名使用小写英文，多个单词以 `-` 连接。静态用例可重复使用，文件名不带运行时间或设备实例标识。
