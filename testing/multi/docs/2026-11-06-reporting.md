# 汇报总结

目标：提供结果汇总、可追溯的过程记录和直观的统计数据。

## 汇报形式

报告放在 `reports/<runId>/`。总结和统计使用固定文件名，过程记录按实际需要组织：

| 形式 | 文件 | 内容 |
|---|---|---|
| 总结 | `summary.md` | 本轮范围、结果汇总、主要问题和待处理事项，不展开执行细节。 |
| 过程记录 | 一个或多个文件，格式按需，可混合使用 | 清晰记录关键操作、结果、异常、排查、修复及复验过程，关联原始日志和证据，便于追溯与排查。 |
| 统计 | `statistics.csv` | 二维表，展示用例、设备平台、单设备／多设备、正向／逆向、执行及复验结果等维度，便于筛选和比较。 |

## 规则

1. 三种形式通过 `runId` 和用例标识关联，能从总结或统计定位对应过程及证据；`runId` 遵循[执行用例的轮次规则](2026-11-06-test-execution-troubleshooting.md)。
2. 每轮独立统计，不混合其他轮次或开发调试历史；需要正式结果时重新完整执行一轮，不增加专门的模式管理。
3. 首次执行与各次复验分别保留，复验通过不能覆盖首次失败；用例数量与执行次数分别统计。
4. 过程记录引用本轮 `tmp/<runId>/` 中的原始日志和证据；日志与报告中的敏感数据遵循[主流程日志规则](2026-11-06-test-execution-flow.md)。
5. CSV 每行对应已登记用例的一次尝试，准入失败也保留；设备分类当前为 `multi`。重复汇报可重新生成总结及统计，不能覆盖原始执行报告。列定义、结论判定及证据依赖见[执行规格](../../../docs/spec/2026-11-06-testing-v2-spec.md)。
6. 接收 `ExecutionResult` 时核对执行序号、固定用例定义、报告摘要及证据；交付 `ReportingResult` 前检查 CSV 无遗漏或重复、总结计数一致、引用可定位。类型与验收规则见[执行规格 §1.4](../../../docs/spec/2026-11-06-testing-v2-spec.md#14-交付格式与接收验收)。测试失败记录正常汇报；汇报自身返工不重跑业务用例，原始证据缺失必须如实保留缺口。
