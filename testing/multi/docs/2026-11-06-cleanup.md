# 必要清理

目标：清理不再需要的运行产物，保证后续执行不受影响。

## 调用时机与类型

可在任务完成后或下次执行前调用。支持选择一个或多个类型，也可选择全部类型；运行产物可按 `runId` 选择轮次。

| 类型 | 登记产物的允许位置与内容 |
|---|---|
| 缓存 | `tmp/<runId>/` 内的运行输入副本及可再生临时文件。 |
| 日志 | `tmp/<runId>/` 内的日志及过程证据。 |
| 构建 | `build/<runId>/` 内本工具保留的构建副本及缓存。 |
| 报告 | `reports/<runId>/` 内已登记的总结、过程记录、统计文件及 `flow-report.json` 等运行器报告。 |

## 清理边界

1. 仅清理明确属于上述类型且不纳入 Git 的文件或目录，不将所有 Git 忽略项作为清理对象。
2. 生成的 Dart 源码不清理，包括 `lib/accounts.g.dart`；选择全部类型时也保留。
3. 不删除正在执行的任务所需文件。
4. 尚待排查的失败记录及证据应保留；保留报告时，同时保留其依赖的必要证据，避免引用失效。
5. 选择全部类型同样遵守以上边界。缓存、构建产物可重新生成；日志、报告按实际保留需求清理。
6. `config/` 下的持久配置、生成输入、example 的构建目录、Pods、工程及全局依赖缓存不归本工具清理；同一路径不重复分类，也不通过符号链接越出允许范围。
7. 以 `run.json` 的任务、故障和产物引用判断保护范围；清理中保留该索引，由编排层按实际删除结果更新。具体删除条件遵循[执行规格 §7](../../../docs/spec/2026-11-06-testing-v2-spec.md#7-必要清理)。
8. 删除前验收产物归属及保护依据，引用不明不删除。交付 `CleanupResult` 的删除、保留、失败清单须覆盖本次选中路径且不重叠；核验路径不存在后才能登记已删除。字段及接收检查见[执行规格 §1.4](../../../docs/spec/2026-11-06-testing-v2-spec.md#14-交付格式与接收验收)。
