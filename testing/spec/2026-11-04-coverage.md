## 契约与新增核对

- 输入：[API 差异](../../docs/porting/5.0.0/01-api-diff.md)、[契约](../../docs/porting/5.0.0/02-contract.md)、[实现记录](../../docs/porting/5.0.0/03-implementation.md)、[历史验证](../../docs/porting/5.0.0/04-verification.md)、[平版验收](../../docs/porting/5.0.0/acceptance-report.md)。本任务只补已约定的脚本范围，不声称覆盖 171 项全部变更。
- 未读数：清全部后检查 0；前值为 0 时仅证明幂等清理。多设备单聊补实际接收后的非零→零，不能将基线空数据算作该转换。
- 编辑：检查返回正文、attributes，再由 `ChatManager.loadMessage` 读回。305 保留失败证据并核实服务开通情况，不改成功预期。
- 群配置：创建后更新 types=34（maxCount+ext），由 `fetchGroupInfoFromServer` 读回；本次拥有的群才允许销毁。
- 设备：`getCurrentDeviceId` 返回 deviceUUID，与 `fetchLoggedInDevices` 同字段精确匹配；匹配唯一且 resource 非空后才允许踢本端。kickAll 使用专用测试账号并隔离，不能影响其他正在运行的场景。
- 回执：单设备保留混合有效／不可解析 ID 的 native 成功语义；M2/M3 使用接收设备真实消息；不能将 API 返回成功等同于发送方已收到回执。
- `fetch-group-receipt-missing-disabled`：沿用已确认的 Android native 崩溃屏蔽，在报告中明确覆盖缺口；这不是新增失败的自动跳过规则。

## 多设备内容与源码依据

| 场景 | 数据与事件 | 仍需真实执行确认 |
|---|---|---|
| M2 单聊回执 | 两账号；watch 先于发送；匹配 `receipts[].messageId/conversationId/isPeerReceipt`，所有字段在同一个元素匹配 | 双端角色交换、事件到达及回执业务状态 |
| M3 群回执 | REST 创建本次临时群；消息 `isNeedReadReceipt=true`；回调 `readCount`、本地汇总与服务端 `list[].msgId/from.userId` 关联本次消息和接收者 | 群回执服务开通；Android totalCount 可空、iOS 可返回，不强制同形 |
| M1 数据同步 | 显式 dataSyncType=4；两设备同账号；本轮新建临时群，在 B 本轮首次登录前创建；监听 start/finish 的 type=4 和数据库 username/error；登录后 `getJoinedGroups` 必须包含本次 groupId | 同账号并发登录策略；B 登录同步事件及 A 仍在线 |

M1 选择 joinedGroups 的依据：`ChatOptions.dataSyncType` 明确为“登录后自动同步的数据类型”，`ChatGroupManager.getJoinedGroups` 明确读取本地缓存。本轮新 groupId 从未存在于 B 历史数据库，且 B 在建群后首次登录前保持关闭，从而排除历史缓存命中。检查同步 finish.error=null 后再读本地数据；不调用服务端拉群接口来替代自动同步。若并发登录或服务配置不满足，记录环境阻塞，不更换断言。

数据同步事件和多设备事件分别验证，不假定第二设备登录会触发所有类型。`getJoinedGroups`、`fetchGroupInfoFromServer`、`loadMessage`、`getCurrentDeviceId`、`isConnected` 原 SDK 已有，本次仅补 example 共享 registry，人工与 AI 共用。
